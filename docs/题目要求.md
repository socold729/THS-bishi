# 题目要求梳理

来源：[原始题目](../14_开放命题_AINative投资产品创新.md)。已完整阅读；初始文件夹中只有这一个文件，未发现额外附件或项目指令文件。

## 产品设计与价值要求

| 编号 | 必须完成的内容 | 后续可核验的交付依据 |
|---|---|---|
| R01 | 在真实投资工作流中选定明确场景，定义目标用户、问题、核心任务、非目标与成功标准 | 产品说明和具体用户流程 |
| R02 | 证明问题值得解决，有可衡量价值 | 痛点依据、基线、评价指标及验证方法；不得伪造用户研究 |
| R03 | 论证为何需要 LLM/Agent，相对规则、搜索、传统数据产品或人工流程的增量价值 | AI 职责、适用范围、对照方式 |
| R04 | 设计并实现可运行的核心主链路，展示 AI 调用数据和工具完成任务 | 实际可操作的 Web 产品 |
| R05 | 形成数据、工具、状态、反馈、人机协作和风险控制闭环 | 可观察状态、人工介入与错误处理流程 |
| R06 | 通过证据、指标和用户流程验证价值 | 可追溯样例和真实测试；说明失败条件、合规边界、后续验证计划 |

可选场景包括个人投资研究、机构研究协作、投顾运营、交易支持、资产配置、风险管理、投资内容生产和质量治理。这是选题范围，不要求把所有场景全部实现。当前不替用户选题。

## 技术与时间要求

- 做题时间为 **24 小时**。题目未给出本次计时起点、截止时刻或时区，需用户提供，不能自行开始计时或声称剩余时间。
- AI 工具和技术栈开放，鼓励 AI Coding；没有指定框架、语言、数据库、模型供应商或强制 MCP 实现方式。
- 金融数据优先使用扶摇 API/MCP 和 iFinD MCP；能力以实际可调用工具为准。题目没有要求必须同时使用两家。
- 核心流程必须可运行、可通过 Web URL 实际操作，仅 PRD/PPT/Figma/截图不算完成。
- AI 应体现必要价值，不得把“使用了模型”本身当成验证成功。

## 合规与数据边界

| 编号 | 题目硬性要求 | 后续需要验证的行为 |
|---|---|---|
| C01 | 公开仓库不得包含 API Key、用户隐私或受限数据 | 交付前检查仓库、历史、日志、样例与构建产物 |
| C02 | 涉及画像/持仓时使用匿名或构造数据 | 数据来源与构造标识清楚；不冒充真实用户验证 |
| C03 | 不得输出确定性涨跌预测、收益承诺或直接买卖建议 | 包括模型回答、页面文案和异常路径；供应商工具名称不构成题目豁免 |
| C04 | 区分事实、推断与不确定信息 | 输出标签、证据及措辞可核验 |
| C05 | 核心结论可回到原始字段或原文 | 明确来源、时点、单位、统计口径，不以 AI 摘要替代证据 |
| C06 | 数据缺失、冲突、过期、调用失败不得静默生成正常结论 | 明确暴露失败/不足，限制结论并支持适当人工处理 |

补充待确认事项（不是题目已写明的条款）：两家数据的公开 Web 展示、缓存、再分发及原文引用权限尚未确认，不能从“可查询”推导为“可公开发布”。
