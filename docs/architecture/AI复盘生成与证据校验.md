# 明日游资：AI 复盘生成与证据校验

这是现有本地 MVP 的增量实现；第二阶段历史文档、日志与接口记录保留原文。当前不部署公网。

用户选日/风格 → 服务端独立重取真实数据 → 程序计算 → 原子证据包 → OpenAI Responses 严格 JSON Schema → 引用/数值/上下文/规则检查 → Dashboard 报告。

## 风格映射

| 风格 | 实际输入与程序计算 | 专项报告结构 | 明确限制 |
|---|---|---|---|
| 短线 | 四指数当日收盘/日涨跌、涨跌停池总数、有限连板样本最高高度、相邻交易日样本高度差、同日题材原文、涨停池最多200条样本的题材词频、自选收盘/日涨跌 | 情绪分布、梯队变化、高位候选与题材样本 | 词频不是板块收益、热度评分或因果证据；样本不等于完整市场；缺前日样本不能分析晋级率 |
| 波段 | 指数及自选 OHLC 按日/周/月聚合、各周期 MA5/10/20/30/60、周期收盘变化、相对均线位置、当日量/前五日均量、自选相对上证指数日涨跌差 | 趋势结构、相对表现与量能、行业证据边界 | 行业时序/事件缺失不判断轮动；周月边界可能未完成；缺完整窗口留空、缺交易日停算趋势；自选不复权 |
| 价值 | 已披露年度/季度利润表、资产负债表、现金流；营收/净利/同比/利润率、负债合计及占比、现金占比、经营现金/净利；实际返回并验证的指定日PE(TTM)/PB、公告片段；用户自设条件的程序核验 | 经营与财务变化、估值与历史信息、基本面跟踪 | 需要自选；缺/过期财务阻止生成；季度不混算单季与累计、不同期/币种不混算；历史估值真实取数未通过时留空；公告片段非全文，不声称无新变化；用户条件符合不证明投资假设成立 |

## 证据与输出

- 每次取数生成独立 UUID 证据包，每条输入以 `包ID:E序号` 唯一标识。包含报告日、数据/披露日、对象、字段、值、单位、公式、口径、源接口、抓取时间、供应商时间和请求标识。
- 浏览器提交日期、风格、自选代码，以及可选的至多10条价值投资核验条件（标的、枚举指标、比较符、用户自设阈值、条件ID）。不接收浏览器行情、模型提示词或证据；私密假设文字不发给模型。阈值明确为用户输入而非金融事实，实际值由服务端重取与计算。
- `fact` 不允许自由文本。模型选择证据并原样返回值/单位，服务端逐一比对后按确定模板生成正文；同一数字属于其他日期/对象也不能通过。
- `inference` 必须引用同对象证据并带不确定性词，明确标记为 AI 推断，不赋予“事实已验证”状态；叙述不能夹带未绑定数字。`uncertainty` 可无引用，但必须说明不足/无法判断。
- 不存在/重复引用、单位或数值/题材不符、日期/对象不符、Schema 不符、未经支持的因果归因、被规则识别的确定预测/收益承诺/交易指令：整份报告失败，不静默删除后装作正常。
- 对财务旧报告，证据数据日期为披露日，口径含报告期；它们是截至选定日可见资料，不能写成当日新事件。最新行情快照不补历史缺口。
- 财报新鲜度策略：最新可见财报的期末距所选日超过732天或无法确认期末时，停用该公司的财务分析；年度/季度分别检查，所有自选均缺失/过旧则阻止价值报告。用户条件不能绕过财务最低证据门槛。这是产品阈值，不是法定披露期限。正常同比可引用更早已披露同期。
- 风格最低门槛：短线需要至少一项可核验涨跌停池总数或梯队高度；波段需要有效周期趋势/量能证据。只有泛化指数价格时，停止对应报告，不能换个标题继续输出。部分缺失但仍有风格核心证据时才生成明确列出限制的报告。
- 这是程序引用/字段核对和保守规则过滤，不是对自然语言含义的完备证明，也不等于独立数据源对账。AI 推断始终待验证；关键词合规检查仍需扩充语义评估。未取得真实模型结果前不声称模型质量验收通过。

## 模型与密钥

服务端直接调用官方 `https://api.openai.com/v1/responses`，不使用任意代理地址。默认 `gpt-4.1-mini`（可通过 `OPENAI_MODEL` 改为账户有权限且支持结构化输出的模型）。使用 `text.format.json_schema`、`strict:true`、`store:false`；无模型工具调用，无外部检索，无自动重试。来源文字按不可信数据处理，笔记不会发给模型。

官方依据：[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini)。`store:false` 不构成关于平台全部日志保留政策的承诺。

复制模板时保留原金融配置，在私密 `.env.local` 中补充：

```dotenv
OPENAI_API_KEY=你的OpenAI密钥
OPENAI_MODEL=gpt-4.1-mini
OPENAI_TIMEOUT_MS=45000
```

重启本地服务后生成报告。不要使用 `NEXT_PUBLIC_`，不要把真实密钥写入日志或示例。账户额度、模型权限、网络可用性只能通过真实调用确认。

## 状态、取消和边界

- `/api/reports`：POST 生成并等待结果，GET 查询任务，DELETE 按日期/风格/自选取消。任务阶段为 fetching/analyzing/validating/completed/failed/cancelled。
- 浏览器按钮即时锁定；同会话同上下文进行中的任务复用，服务端最多四个活动任务。日期/风格/自选/假设条件共同构成上下文；切换后取消并丢弃旧结果，报告正文和条件配置再核对。
- 使用随机会话 token 与任务 token，任务仅返回给对应 token。只适合当前本地使用，不是账号认证。匿名会话 token 要妥善保存；公网需要账号/访问/额度控制。
- 临时任务保存在有界进程内 Map，完成任务十五分钟后在后续创建时清理，最多64项。进程重启或多实例不能保证保留/去重；长请求在平台结束后不保证继续运行。本轮没有后台队列、数据库、持久报告历史、保存/反馈或跨设备同步。
- 任务总预算105秒，模型默认45秒；超时/拒绝/错误/不完整输出均失败，可手动重试，无静默模拟回退。当前页面刷新不保证恢复报告，日历与笔记原有本地保存照常保留。

## 验证方式

`npm test` 包含明确构造数据/模型 Mock 的风格、数值、证据、取消、错误与合规检查；Mock 不代表真实模型调用成功。`npm run test:e2e` 包含真实供应商回归、明确 Mock 的报告交互和本地服务端参数校验。

`node node_modules/tsx/dist/cli.mjs scripts/verify-ai.mts` 检查本地数据包；存在密钥时尝试一次真实 OpenAI 调用并保存私有样例。没有密钥时记录未尝试，不能交付真实生成示例。公开记录只保存验证状态/计数，金融内容与完整模型响应保存在忽略的 `.cache`。
