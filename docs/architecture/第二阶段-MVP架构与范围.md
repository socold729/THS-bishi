# 盘后 AI｜MVP 范围与架构 v0.1

日期：2026-10-27。本文件继承第一阶段结果，新增设计；原始题目与历史验证记录保留。用户本轮授权设计与开发，但明确不一次完成整个产品。

## 产品与可落地范围

目标用户：白天工作、不能持续盯盘的 A 股个人投资者。核心任务：下班后按自己的投资风格，选择一个已收盘交易日，定位市场变化和自选股变化，理解依据及缺失信息。

产品差异化：策略改变实际请求的数据、程序指标和后续报告章节，不只切换 Prompt。程序负责行情、均线、聚合 K 线、同比和比率；LLM 后续负责证据约束下的信息整合与解释，不计算财务数值。

| 范围 | 本轮实现 | 后续 P0 |
|---|---|---|
| 初次配置与切换 | 三种风格选择、保存、修改，浏览器持久化 | 个性化报告章节和策略提示 |
| 自选股 | 名称/完整代码真实检索、手动增删，最多3只 | 扩容前评估并发与时延 |
| 日期与数据 | 选择近一年日历内已收盘交易日；缺失时停止 | 按需求扩展历史范围与供应商核验 |
| Dashboard | 真实行情、三策略不同数据、程序指标、证据弹窗、缺失/错误状态、桌面与移动布局 | 全市场宽度、行业全量趋势/轮动 |
| AI 报告 | 仅诚实展示“待接入”，没有 AI 结论或示例报告 | 结构化生成、证据检查、事实/推断/不确定性分区、人工反馈 |
| 历史与持久化 | 复盘档案页面明确未接入，配置与自选已持久化 | 报告与证据快照保存、历史详情、反馈 |
| 部署 | 标准 Next.js 生产构建、环境模板 | Vercel 公开部署及发布前授权与访问控制 |

不做：证券账户接入、自动交易、个人交易盈亏、复杂多 Agent、社交；AI 追问与手动交易记录是 P1。

待验证的价值目标：用户能在3分钟内找到所选风格的主要事实与缺口；事实证据覆盖完整；相较通用摘要减少不相关信息。以上是后续评价目标，尚未做用户研究或对照实验，不声称已达到。

## 三策略的数据、指标与分析映射

共同基础：交易日历确认日期，沪深300历史日线提供基准；自选股最多3只。所有数据均真实请求，无演示行情回退。

| 风格 | 本轮实际数据 | 程序指标与处理 | 后续 LLM 组织方式 | 暂不支持的结论 |
|---|---|---|---|---|
| 短线 | 涨停/跌停池、连板矩阵、指数日线；自选不复权日线 | 涨跌停家数读 pagination.total；日涨跌=相邻交易日收盘比；日期匹配的有限连板样本 | 市场结构→分化→自选事件→证据与缺口 | 情绪打分、龙头判定、热点题材归因、全市场宽度；不拿200条股票池或单个指数当全市场 |
| 波段 | 指数与自选股历史日线；行业目录已验证但全量时序未接入 | MA5/20/60；日线按自然周/月聚合 OHLC 与量额；当日量÷前5日均量；缺交易日/样本不足则留空 | 量价事实→趋势一致/分化解释→行业背景→需要跟踪的问题 | 完整行业轮动、产业事件；不依据指数走势生成行业排名 |
| 价值 | 已披露年度利润表、现金流量表；最新估值单独标时；资产负债表/指标已验证但未进入本轮面板 | 净利率=合并净利润÷收入；营收同比需相邻年度；经营现金流÷同报告期净利润；分母≤0留空 | 经营与盈利→现金流质量→估值口径→投资假设待核实项 | 没有公告原文时不判断假设已改变；无历史估值时不回填最新 PE；不提供高低估结论 |

明确口径：

- K 线图本轮展示按日/周/月周期的收盘走势与 MA；已实现 OHLC 聚合，完整蜡烛图可在后续扩展。边界周/月可能尚未完成，界面明示。
- 自选股目前使用不复权日线，分红送转会影响技术指标，证据中明示；未将现有接口直接当作历史时点复权数据库。
- 历史财务同时过滤 report_date_ms 和 period_end_ms 不晚于所选日；未知披露日期不使用。供应商可能有事后修订，本轮不宣称 point-in-time 历史版本还原。
- 估值只在最新已收盘日页面展示“最新快照参考”，不称为该日历史估值，不进入历史归因；其他日期直接不可用。
- 上游 timestamp 是供应商时点，不直接等于成交日/披露日。原始业务日期与抓取时间分开记录。
- 关键数值在证据弹窗显示来源、字段、原始输入、单位、口径、request_id 与时间；程序指标说明公式。不借数据可达性声称已独立审计数值。

## 技术架构

采用 Next.js App Router + TypeScript，Tailwind CSS + shadcn/ui 风格基础组件、Recharts。保留单应用、单服务端金融访问层；不引入任务队列、微服务或多 Agent。

```mermaid
flowchart LR
  U[配置 / 自选 / 日期] --> P[浏览器配置存储]
  U --> R[Next Route Handler]
  R --> V[参数 / 交易日检查]
  V --> S[按策略分支取数]
  S --> F[扶摇服务端客户端]
  F --> M[程序指标 / 缺失检查]
  M --> E[字段证据包]
  E --> D[Dashboard]
  E -.下一轮.-> A[LLM结构化分析]
  A -.-> C[证据与合规检查]
  C -.-> H[报告保存 / 历史 / 反馈]
```

本轮链路：配置→策略选择→数据获取→程序计算→字段证据→Dashboard。AI 分析→AI结论证据检查→报告→反馈属于下一轮；不能将当前链路称为完整 AI Native 产品已完成。

服务端处理：

1. 校验风格、合法日历日期、最多3个完整证券代码；请求失败返回明确状态。
2. 交易日历确认最近已收盘日；盘中当天、未来日期、非交易日或超日历范围停止。
3. 同一入口依策略请求不同端点，低并发顺序执行；每个请求有超时、HTTP/业务码/响应结构检查，不自动密集重试。
4. 保留 null；没有对应日线不替换成前一日；缺交易日不继续算均线。
5. 响应保留 ready / partial / blocked，逐数据源 ready / empty / unavailable / error；浏览器切换时取消旧请求和清除旧展示，避免结果串策略。
6. 凭据只在服务端模块，绝不使用 NEXT_PUBLIC_；禁止对任意主机转发密钥；路由只提供受控业务查询，不暴露通用代理。

## 数据结构和持久化

| 结构 | 字段与职责 | 本轮状态 |
|---|---|---|
| Preferences v1 | style、period、watchlist[{code,name}]、updatedAt；Zod校验、限额、去重 | 已实现，localStorage持久化 |
| DashboardData | strategy/date/latestClosedDate、metrics/bars/stocks/ladder、coverage/evidence/messages、状态 | 已实现，按请求返回，不持久化金融数据 |
| Evidence | id、source、endpoint、requestId、fetchedAt、sourceTime、scope、unit、原始字段观察值 | 已实现，内存展示 |
| Metric | label/value/unit/note/evidenceIds；null与0区分 | 已实现 |
| Report（计划） | id/style/date/configSnapshot、facts/inferences/uncertainties、evidenceSnapshot、模型与生成版本、验证状态 | 下一轮 |
| Feedback（计划） | reportId、useful/not-useful、comment、createdAt | 下一轮 |

当前单用户、无登录：浏览器是配置的持久化边界，同一实现可用于本地和 Vercel。不会将个人自选写到全站共享配置文件。用户明确知道清理浏览器数据会丢失配置、不跨设备同步。

下一轮报告采用浏览器 IndexedDB 保存报告与授权允许的证据快照，避免 Vercel 无持久文件系统的问题；通过 Repository 接口与 UI 解耦。需要跨设备/账号时，再引入托管 Postgres 与身份校验，不在本轮搭建空数据库。报告保存前需确定数据缓存/再分发授权。

## 后续开发顺序

1. 用户提供 OpenAI 服务配置后，接入结构化报告；模型只消费证据包，不能自行补新闻、计算指标或越过失败状态。
2. 实现 claim.evidenceIds 的非空/有效性检查、数值一致性、禁止直接买卖与确定性承诺、事实/推断/不确定分区；人工抽查原文与口径。
3. 报告保存、历史、详情及反馈组成可实际操作闭环，加入失败恢复与测试。
4. 有余力再扩展行业时序/宽度；iFinD 实际成功且可溯源后再启用新闻公告。
5. 部署前确认数据公开展示权限、模型与部署凭据，增加访问/调用预算控制，外部验证 URL 和完整主链路。当前没有部署，也没有公开访问承诺。

## 用户追加界面迭代：复盘月历与每日笔记（2026-10-27）

当前市场概览为四指数与涨跌停公共数据，蜡烛K线已实现，替代最初的沪深300收盘折线。四指数采用最多两路并行，其他数据保持有界取数；预算和失败状态继续保留。

新增 ReviewCalendar（月视图）、ReviewNoteEditor（上下两处同状态）、useReviewNotes（日期索引状态/存储事件）、review-notes.ts（按日存储与校验）、review-calendar.ts（月网格）、ladder.ts（降序/同日题材关联）。

笔记独立于AI报告：每个日期一个版本化localStorage键，文本不上传；同步保存避免跨日防抖回调串写。空白删除、超长/坏格式拒绝、存储失败保留草稿并警告。日历蓝点只由实际非空笔记产生，不预填参考图示例。两处编辑与跨标签页同步，跨设备云同步未实现。

数据完整性从右侧卡片迁移到页底可展开状态，不丢失来源和异常信息。梯队题材来源于所选日limit_up_reason，不用公告或模型推测热点。当前仍非完整AI报告产品，AI分析、报告历史与反馈不受本轮笔记功能的完成状态替代。
